## 概要
アルバイト先の「紙のマニュアル特有の不便さ」を解消するために開発した、FlaskベースのWebアプリケーションです。  
実機での試験運用を通じ、**「技術的な利便性」と「飲食店における衛生・機密保持の制約」**の両面からアプローチしました。

## 開発の背景：現場で感じた4つの課題
1. **検索性の低さ** 数十種類のレシピから目的のものを探すのに時間がかかる。
2. **作業スペースの不足** 紙のマニュアルを広げると調理スペースを圧迫してしまう。
3. **更新の難しさ** メニュー変更の際、全ての紙マニュアルを差し替える手間が発生する。
4. **情報の不透明さ** 締め作業の多くが「口頭伝承」や「個人メモ」に頼っており、公式な手順が整備されていない。

## 解決した課題
- **検索性の向上**: キーワード検索で即座にレシピを表示し、接客スピードを維持。
- **省スペース化**: 狭いキッチンでも場所を取らないスマホでの確認を実現。
- **教育コストの削減**: 新人が聞きづらい「締め作業」の手順を可視化し、ミスを防止。

> ### 運用上の気づきとリスク管理
> 開発・運用の過程で、以下の「飲食店ならではの制約」を再認識しました。
> - **衛生面・マナー**: 調理中のスマホ操作制限（衛生的・接客的観点）。
> - **情報流出リスク**: 店舗固有レシピを外部サーバーで公開することへの慎重な配慮。
> - 
> **現在の運用方針：** > これらを踏まえ、現在は「個人の予習・復習用ツール」として活用し、今後はセキュリティ機能を強化する方針です。

## 技術スタック
- **Backend**: Python 3.x / Flask
- **Frontend**: HTML5 / CSS3 (Responsive Design)
- **Deployment**: Render
- **Version Control**: GitHub

## 主要機能
- **メニュー検索**: 入力に合わせて即座にメニューをフィルタリング。
- **カテゴリー切替**: 「すべて/ドリンク/フード/締め作業/その他」のタブ表示。
- **現場主導の編集**: 従業員が情報を更新し、現場の声を反映できる仕組み。
- **画像ガイド**: 盛り付けなどを視覚的に理解できる写真表示対応。
- **モバイルファースト**: 店舗利用を想定した直感的なUI設計。
