バイト先専用・デジタル業務マニュアル（プロトタイプ）
公開URL: https://workplace-manual-app.onrender.com
(※無料プランのため、起動に30秒〜1分ほどかかる場合があります)

概要
アルバイト先の「紙のマニュアル特有の不便さ」を解消するために開発した、FlaskベースのWebアプリケーションです。
実機での試験運用を通じ、「技術的な利便性」と「飲食店における衛生・機密保持の制約」の両面からアプローチしたプロジェクトです。

開発の背景：現場で感じた4つの課題
検索性の低さ: 紙のマニュアルでは数十種類のレシピから目的のものを探すのに時間がかかる。

作業スペースの不足: 紙のマニュアルを広げると調理スペースを圧迫してしまう。

更新の難しさ: メニュー変更や追加の際、全ての紙マニュアルを差し替える手間が発生する。

情報の不透明さ: 締め作業の多くが「先輩からの口頭伝承」や「個人メモ」に頼っており、公式なマニュアルが整備されていない。

解決した課題
検索性の向上: キーワード検索で即座にレシピを表示し、接客のスピードを落とさない。

省スペース化: 狭いキッチンでも場所を取らないスマホでの確認を可能にした。

教育コストの削減: 新人が聞きづらい「締め作業」の細かい手順を可視化し、作業ミスを防止。

運用上の気づきとリスク管理
開発・運用の過程で、以下の「飲食店ならではの制約」を再認識しました。

衛生面・マナー: 調理中のスマホ操作は衛生的・接客的に制限があること。

情報流出リスク: 店舗固有のレシピを外部サーバーで公開することへの慎重な配慮。
これらを踏まえ、現在は「個人の予習・復習用ツール」として活用しつつ、今後はセキュリティ機能を強化する方針です。

技術スタック
Backend: Python 3.x / Flask

Frontend: HTML5 / CSS3 (レスポンシブデザイン)

Deployment: Render

Version Control: GitHub

主要機能
メニュー検索: 入力した文字に合わせて即座にメニューを表示。

カテゴリーフィルタリング: 「すべて/ドリンク/フード/締め作業/その他」のタブ切り替え。

現場主導の編集: 実際に働く従業員が情報を更新し、現場の声を反映できる仕組み。

画像ガイド: 盛り付けなどを視覚的に理解できるよう写真表示に対応。

モバイルファースト: 店舗での利用を想定したUI設計。

今後のアップデート予定
セキュリティ強化: 特定の関係者のみが閲覧できる「パスワード機能」の追加。

作業管理: 締め作業の完了状態を記録できる「動的チェックリスト」の実装。
